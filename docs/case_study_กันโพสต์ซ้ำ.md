# เคส: ระบบโพสต์ออโต้ลงซ้ำ → แก้ให้ "สั่งซ้ำแล้วไม่พัง" (19 พ.ย. 2569)

> ใช้เล่าในพอร์ต/สัมภาษณ์ฝึกงานสาย data · ตัวเลขทุกตัวมาจากล็อกจริงใน `posting/โพสต์บอล.md`

## บริบท
ร้านขายไอเทม Blade Ball โปรโมตในกลุ่ม Facebook 4 กลุ่มที่มีสมาชิกเกิน 3 หมื่นคน (รวมราว 3.4 แสนคน)
ลงกลุ่มละ 6 โพสต์ = **24 โพสต์ต่อรอบ** ผมเขียนสคริปต์ `autopost.py` ทำหน้าที่คุมคิว ตัวคิวเก็บในไฟล์ JSON เพื่อให้หยุดกลางทางแล้วกลับมาทำต่อได้
ผลที่ได้คือ ขั้นตอนที่ต้องสั่งเครื่องมือต่อหนึ่งโพสต์ลดจาก **~8 ครั้งเหลือ 3 ครั้ง**

## ปัญหา
รอบหนึ่งลงครบ 24/24 ตอน 12:50 สามนาทีต่อมามีการสั่ง "โพสเลย" อีกครั้ง ตอนนั้นไฟล์บันทึกสถานะเก่ายังเขียนว่าคิวค้างอยู่ 3/24
สคริปต์เห็นว่าคิวหมด จึงเริ่มรอบใหม่เองโดยไม่แจ้งอะไร และลงโพสต์ซ้ำในกลุ่มใหญ่สุด (1.6 แสนคน) ทันที ผลคือต้องตามลบเอง และเสี่ยงโดน Facebook จับว่าเป็นสแปม

## หาต้นเหตุ
- เทียบข้อมูล 3 แหล่ง ได้แก่ ไฟล์คิว ล็อกโพสต์ และหน้า "โพสต์ของฉัน" บน FB → พบว่าไฟล์สถานะผิด ส่วนคิวกับล็อกถูกต้อง
- ต้นเหตุจริงคือ **"คิวหมด" มีได้ 2 ความหมาย** คือ ยังไม่เคยเริ่ม กับ เพิ่งลงครบ แต่โค้ดตีความเป็นอย่างแรกเสมอ
  ระบบจึงไม่ **idempotent** (สั่งคำสั่งเดิมซ้ำแล้วผลลัพธ์ไม่เหมือนเดิม)

## วิธีแก้
1. ใช้ **ล็อกโพสต์เป็นแหล่งความจริงแหล่งเดียว** ก่อนเริ่มรอบ สคริปต์จะอ่านเวลาที่ลงล่าสุดของแต่ละกลุ่มจากล็อก
   (ลบโพสต์บน FB ก็ลบแถวในล็อกด้วย ล็อกจึงตรงกับของจริงที่สุด และไม่หายเวลาโฟลเดอร์คิวถูกล้าง)
2. รอบใหม่จะเอาเฉพาะกลุ่มที่ลงไปแล้วอย่างน้อย 3 ชม. หรือยังไม่เคยลง และเรียงกลุ่มสมาชิกมากไปน้อย ขยายจาก 4 กลุ่มเป็น 15 กลุ่ม
   ถ้าทุกกลุ่มเพิ่งลง จะตอบ `TOO_SOON` แล้วหยุด ถ้าตั้งใจลงซ้ำ เจ้าของต้องสั่ง `force` เอง
3. ลงให้ครบทีละกลุ่มก่อนย้ายกลุ่ม ถ้าโดน FB บล็อกกลางทาง กลุ่มที่สำคัญที่สุดจะลงครบไปแล้ว
4. เขียนเทสต์ 11 เคส (`posting/test_autopost.py`) ครอบคลุม ทุกกลุ่มเพิ่งลง / เฉพาะกลุ่มใหญ่เพิ่งลง / ห่างพอแล้ว / force / ไม่มีล็อก / ล็อกไม่เรียงเวลา / done+undo / ตั้งค่ากลุ่มซ้ำ
5. รวมขั้นตอนเป็น **Claude skill** (`.claude/skills/fb-autopost/SKILL.md`) ที่มีตาราง "ห้ามพลาดซ้ำ" 11 แถว จากบั๊กจริงตลอด 3 วัน ทุกแชทต้องอ่านตารางนี้ก่อนเริ่ม

## สกิลที่เคสนี้แสดง
- Debugging โดยเทียบข้อมูลหลายแหล่ง (คล้ายการทำ data reconciliation)
- ออกแบบระบบให้ idempotent และ fail-safe
- เขียนเทสต์กันปัญหากลับมา (regression test)
- กำหนด single source of truth ให้ข้อมูลสถานะ
- ใช้ AI agent กับงานธุรกิจจริงโดยมี guardrail (เทสต์ + สคริปต์กำหนดขั้นตอน + ให้คนยืนยันก่อนทำสิ่งที่เสี่ยง) ไม่ปล่อยให้ AI ตัดสินใจเองทั้งหมด

## บรรทัดใส่เรซูเม่ (อังกฤษ)
- Built an AI-agent workflow (Claude skill + resumable Python queue) that posts a small business's listings to 15 Facebook groups, cutting browser-tool steps per post from ~8 to 3.
- Fixed a non-idempotent restart bug that caused a duplicate post: the queue now reads the post log as its single source of truth and only schedules groups not posted in the last 3 hours, backed by 11 regression tests.
